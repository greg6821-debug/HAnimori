# Архитектура

Настольное приложение AniMori на Tauri 2. Ядро — `packages/core/src/`, экраны — `src/app/`, оболочка — `src-tauri/`.

Приложение ведёт только аниме: манги нет ни в экранах, ни в отборах, ни в запросах.
Список односторонний — приезжает из AniList по входу, с Шикимори по нику и файлом
выгрузки MyAnimeList, живёт на устройстве и на сервер не уходит. Наружу уходит
выгрузкой в XML и копией в облако, по действию человека — `STORAGE.md`.

Данные склеиваются: каталог и списки — AniList, русские названия — датасет
`foulnike/animori-data`, чего в нём нет — Шикимори, персонажи и авторы —
Шикимори, музыка — AnimeThemes, видео — Aniliberty и Kodik. Собирание и приёмка
датасета — `DATA.md`.

## Слои

```
apps/windows/src/app/      знает разметку
        ↓  алиасами @/api, @/bridge, @/core, @/utils
packages/core/src/          api, bridge, core, utils
```

Правила зависимостей и инварианты — в `CONVENTIONS.md`.

## Мост

`packages/core/src/bridge/` прячет платформу за одним контрактом: что умеет среда,
но не как. Ядро не спрашивает, где работает.

| Группа             | Как устроено                                       |
| ------------------ | -------------------------------------------------- |
| `storage`          | `animori_storage_read` / `animori_storage_write`   |
| `http`             | плагин http, запрос идёт из Rust, без CORS         |
| `anilist`          | команда `animori_anilist_query`                    |
| `clipboard`        | плагин clipboard-manager                           |
| `shell`            | перезагрузка, полный экран, внешняя ссылка         |
| `files`            | `animori_file_read` / `animori_file_write`         |
| `exportFile`       | выбор папки и запись файла: XML и звук темы        |
| `proxyDiagnostics` | щуп прокси из Rust, живой запрос и состояние входа |

`anilist` отделена от `http`: адрес и пропуск живут только в Rust, наверх идёт
тело запроса и просьба его подписать — токен не покидает оболочку.

`files` отдаёт наружу имя, а не путь: каталог выбирает оболочка. Имён два —
`animori-snapshot.json` и `animori-dataset.json`, белый список в `files.rs`, потолок
записи 8 МБ, запись идёт во временный файл с переименованием.

`exportFile` устроена наоборот: путь выбирает человек диалогом, сторожем служит
окончание имени. Единственное место, где программа пишет вне своего каталога, и
пишет туда только `.xml`.

У `files` и `exportFile` есть признак `available`: вне оболочки обе группы есть,
но ничего не делают.

## Слой запросов

`api/rate-limit.ts` заводит ограничитель на источник, а не на домен: лимит
считается по IP, и зеркала делят один бюджет.

| Источник                                                 | Интервал   | Потолок за минуту           |
| -------------------------------------------------------- | ---------- | --------------------------- |
| Шикимори, AnimeThemes, GitHub, Aniliberty, Kodik | 300 мс     | 60                          |
| AniList                                                  | из потолка | старт 30, предохранитель 90 |

`acquireSlot()` — единственный вход, слоты по одному. Сверх минутного окна
держится секундное: три запроса в секунду в первые десять секунд после пуска, дальше
восемь.

Один ограничитель у Шикимори делят `shikimori.ts` и `shikimori-people.ts`, а
`shikimori-user.ts` идёт мимо него — там единичные запросы по кнопке.

Плавающий потолок включён только у AniList: остальные заголовков не присылают.
Ответ 429 режет потолок вдвое и закрывает рост на пять минут, ниже шести запросов
в минуту потолок не опускается.

### AniList

`api/anilist.ts` — единственная точка GraphQL и держатель общей паузы; запросов
на запись нет. Заголовки читаются из любого ответа, включая ошибки, в любом
регистре имени: мост в Rust имена понижает. Нулевой `x-ratelimit-remaining` ставит
паузу до `x-ratelimit-reset`, но не длиннее минуты. Отказ сервера (403, 408, всё
от 500) — пауза 30 секунд с удвоением до пятнадцати минут, успех обнуляет серию.
Паузу дольше десяти секунд вызов не высиживает, а бросает ошибку с остатком.

403 неоднозначен: AniList отдаёт его и при закрытии доступа, и когда сервис лёг.
При отказе в журнал выписываются `cf-ray`, `cf-mitigated`, `cf-cache-status`,
`retry-after`, `x-ratelimit-*` и `server`; тела ответа в журнале нет.

## Хранение

Пять мест, различает их цена потери.

| Что                           | Где                      | Если потеряется         |
| ----------------------------- | ------------------------ | ----------------------- |
| Ответы сети, русские карточки | IndexedDB                | добудется заново        |
| Снимок списка                 | хранилище моста          | правки взять негде      |
| Второй экземпляр снимка       | файл приватного каталога | остаётся главный        |
| Датасет названий              | файл приватного каталога | скачается заново        |
| Копия списка                  | облако владельца ключа   | остаётся местный снимок |

Ссылки на видеопоток не хранятся нигде: они подписаны и просроченными становятся
сами.

### IndexedDB

База `AniMoriSuperDB`, версия 7, четыре физических склада: `mediaCache` и
`malCache` по своему ключу, `franchiseCache` и `posterCache` по числовому.
`shikiCache` — прежнее имя `mediaCache`: переехал миграцией 6 и остался в коде
только псевдонимом.

| Префикс    | Что лежит                               |
| ---------- | --------------------------------------- |
| `NAME1_`   | русское имя тайтла                      |
| `NONAME1_` | отказ: русского имени нет               |
| `RU4_`     | русская карточка: имя, описание, оценки |
| `LOOK3_`   | облик: обложка, цвет, части, формат     |
| `MED3_`    | карточка Шикимори                       |
| `CHR3_`    | персонажи                               |
| `STF4_`    | авторы                                  |
| `THEMES2_` | музыкальные темы                        |
| `RATE1_`   | оценки площадок                         |
| `PLAY1_`   | метка доступности видео                 |
| `ALIB1_`   | соответствие Aniliberty                 |
| `SHOT1_`   | кадры и ролики тайтла                   |

Отдельно живут `KODIK1_` в `kodik.ts` и `SHELF2_`, `GENRE1_`, `RECS1_`, `TAGS1_all`
в `anilist-catalog.ts`: в общей описи они не перечислены, и `getDbStats` складывает
их в `other`. Цифра в префиксе — версия формы записи: форма меняется, цифра растёт,
старые записи перестают находиться.

Стор `posterCache` хранит сам постер байтами, а не его адрес; ключ — номер тайтла,
значение — `Blob`, размер и метка времени. `getDbStats` считает его отдельной
строкой, свой счёт у него и у `posterStats()` в `core/posters.ts`. Постеры кладутся
только для своей полки, при запуске, в фоне: `main.ts` берёт адреса из склада
обликов и зовёт `prefetchCovers`, локальный адрес подставляет `peekLook` в
`core/media-looks.ts`, реактивность у моста своя — `app/covers.ts`.

Открытие базы разрешается всегда и ровно один раз: соединением либо `null` по
ошибке или по таймауту в семь секунд. Единого срока годности нет: `CACHE_TIME`
бесконечен, срок у каждого вида свой и лежит в `core/cache-life.ts`, проверка при
чтении — `isFresh`. Разброс ±20 % считается от ключа.

### Снимок

Одна запись в хранилище моста, `AM_SNAPSHOT`, плюс второй экземпляр в файле
приватного каталога. Форма — шестая версия: её повышение обесценивает все местные
снимки, и список при первом запуске переносится заново. Код разведён: снимок —
`core/snapshot.ts`, общее звено записей — `core/store-chain.ts`.

### Журнал активности

Отдельная запись `AM_ACTIVITY` в `core/activity.ts`, мимо снимка: `updatedAt` — одно
поле на тайтл, оно перезаписывается при каждой правке. Журнал append-only, потолок
6000 событий. Пишет его одна точка — `editEntry` в `core/collection.ts`; вид
правки выбирает `activityOfEdit`, даты начала и конца в журнал не пишутся. Плеер не
пишет ничего: место остановки и история просмотра живут своим ключом
(`screens/player-keep.ts`). Старые дни из снимка не восстанавливаются — сетка
показывает только то, что человек отметил сам.

## Слой данных

Порядок пуска держит `app/main.ts`: `loadSettings()`, `startAppearance()`,
`installGlobalErrorHandlers()`, монтирование `App` и сразу за ним `hideBoot()`,
`initCollection()`, `initDatasetNames()` и `updateDatasetNamesInBackground()`.
Настройки первыми — иначе первая перерисовка идёт по умолчаниям; коллекция
поднимается после монтирования, иначе чтение снимка задержало бы первую отрисовку.
Заставка старта (`#boot`) лежит в `src/app/index.html` и снимается после монтирования.

Записи коллекции живут словарём по номеру тайтла; правка идёт через `editEntry()`
и никуда не уходит — ложится в память и в снимок, а правка неизвестного тайтла
создаёт пустую запись. Перенос выбирает человек: `mergeFromServer` (основа — ответ
сервера, чего там нет, остаётся) и `replaceFromServer` (список становится ровно
серверным, с подтверждением). Тот же выбор у `pullFromShikimori` и
`pullFromMalFile`, с оговорками: хозяин списка не меняется, ответ забирается
целиком до изменения памяти, а у файла метки правки может не быть — запись считается
старейшей. Рядом — `unlinkCollection` и `forgetCollection`.

Путь чтения имени четырёхуровневый: память запуска, датасет, склад, сеть. Ответ
«такого номера в файле нет» запоминается, сетевой сбой — нет. Описание и оценки
идут тремя уровнями: память, склад карточек, сеть. Разрез «имя» и «карточка»
сделан в `core/media-title.ts`: `NAME1_` и `RU4_`.

Пути наружу: `core/mal-xml.ts` собирает опись MyAnimeList и разбирает чужую, файл
пишет `app/save-file.ts`, читает `app/load-file.ts` (gzip распознаётся по подписи),
номера сводит `api/mal-import.ts`; облачную копию держат `core/cloud.ts` и
`core/cloud-file.ts`. Подробности — `STORAGE.md`.

Два модуля в `core/` не имеют вызывающих: `accent.ts` и `qr.ts`.

## Прокси и учёт сети

AniMori работает с AniList через прокси-канал — настройку соединения, канал — часть приложения.

- `core/proxy.ts` — настройка и ключи хранилища. Модуль чистый: его читает и
  прикладной код, и мост.
- `core/proxy-settings.ts` — та же настройка со стороны разметки плюс вопрос о
  перезапуске. Разбор значений обязан совпадать с Rust: ключи читают `proxy.rs`,
  `anilist.rs` и этот модуль.
- `core/net-health.ts` — суждение о доступности (`getOutage`) и одна проба
  (`runProbes`). Учёт идёт по идентификаторам `anilist:graphql`,
  `shikimori:<домен>`, `animethemes`, `aniliberty`; адресов
  модуль не знает. Источник считается проблемным после двух неудач подряд, 404
  считается успехом, отказ авторизации, 429 и отмена не учитываются.

Настройка не применяется на ходу: канал задаётся аргументом при запуске окна,
нужен перезапуск. Пароль прокси лежит в `animori-settings.json` открытым текстом.
Ни одного адреса прокси в коде нет — в интерфейсе и документации это настройка
соединения.

## Оболочка

### Окна

Окно `main` грузит сборку из `dist/app`, окно `login` держит форму входа. Больше
окон нет: `app.windows` в `tauri.conf.json` пуст, оба окна создаются кодом.
Внешние ссылки уходят в системный браузер командой `animori_open_external`.
Перехвата навигации в коде нет, глобального объекта Tauri в окне нет
(`withGlobalTauri: false`), политика содержимого задана в `tauri.conf.json` ([CSP.md](../CSP.md)).

### Команды и права

Разрешения одни — `capabilities/default.json`, и только окну `main`: окно входа
грузит чужую страницу.

| Команда                                                          | Зачем                                                    |
| ---------------------------------------------------------------- | -------------------------------------------------------- |
| `animori_anilist_query`                                          | запрос к AniList из Rust                                 |
| `animori_auth_start`, `_submit`, `_status`, `_logout`            | вход, ручная вставка пропуска, срок, выход               |
| `animori_file_read`, `animori_file_write`                        | снимок списка и датасет в профиле                        |
| `animori_export_pick_dir`, `animori_export_write`                | выгрузка XML                                             |
| `animori_track_pick_dir`, `animori_track_write`                  | запись звукового файла темы                              |
| `animori_proxy_status`, `animori_proxy_probe`                    | исход настройки сети и проба адреса                      |
| `animori_open_external`                                          | ссылка в системный браузер                               |
| `animori_devtools`                                              | инструменты разработчика                                 |
| `animori_cast_panel`                                             | системная панель трансляции, только Windows              |
| `animori_reload`, `animori_restart`, `animori_toggle_fullscreen` | перезагрузка страницы, перезапуск процесса, полный экран |

`animori_reload` и `animori_restart` путать нельзя: **перезагрузка страницы не
применяет прокси** — ключи запуска WebView2 читаются один раз, при создании
первого окна.

Внешние адреса для `http:default` перечислены в том же файле прав, включая
`cloud-api.yandex.net` и раздатчики файлов Яндекса. Список живёт до сети: промах
плагин отклоняет до всякого запроса.

Новая команда — всегда три места: `invoke_handler` в `src/lib.rs`, `COMMANDS` в
`build.rs` и `permissions` в `capabilities/default.json`.

### Вход

Форма открывается в окне `login`, которое идёт через наш прокси. Пропуск
возвращается на `http://127.0.0.1:48513/relay`: приёмник слушает только петлю и
гаснет через пять минут. Возврат принимается только с `state` — одноразовым nonce,
который приёмник подставляет в запрос входа и сверяет на `/token`; без совпадения
возврат отклоняется. Разметка видит только факт входа и срок, ручная вставка —
запасной путь. **Адрес возврата задан не в репозитории**, а в консоли
разработчика AniList: при смене адреса приёмника правится консоль, а не исходник.

### Прокси

Трафик идёт двумя каналами: страница — через ключи запуска WebView2, запросы из
Rust — через опцию клиента. `proxy.rs` сводит всё к одному из четырёх исходов:
выключено, неверные данные, адрес не отвечает, применено; исход доступен
интерфейсу командой `animori_proxy_status`, читатель — `ProxyBox.vue`.
Прокси, который соединение принимает и не пускает наружу, TCP-щупом не отличить:
второй шаг живёт в ядре (`api/proxy-check.ts`). За пределами Windows исхода
`Applied` не бывает — переменную окружения читает только WebView2.
`proxy_auth.rs` подставляет логин с паролем на событие базовой авторизации, только
под Windows.

### Сборка

Режим один: корень `src/app`, выход `dist/app`.

- `@bridge-impl` → `packages/core/src/bridge/TauriBridge.ts`; `@/api`, `@/bridge`,
  `@/core`, `@/utils`, `@` — соответствия каталогов, `@` последним. Те же
  соответствия в `tsconfig.json` и `tsconfig.shared.json`.
- `__ANIMORI_PLATFORM__` = `'app'`, `__ANIMORI_VERSION__` — из `package.json`.
- `minify: 'esbuild'`, `target: 'es2022'`, `emptyOutDir: true`.
- `hls.js` берётся лёгкой сборкой `hls.light.mjs`; путь ищет `require.resolve`.

`beforeBuildCommand` и `beforeDevCommand` зовут `npm run build:app`,
`frontendDist` смотрит на `dist/app`, а `build:app` начинается с `typecheck:all`.
`npm test` гоняет vitest по `tests/**/*.test.ts`, мост подменяется
(`@bridge-impl` → `packages/core/tests/mocks/bridge.ts`), окружение — `happy-dom`.

Номер версии один, в `package.json`; `tauri.conf.json` берёт его строкой
`"version": "../package.json"`. Теги выпуска — `windows-v<версия>`.

### Выпуск и обновление

Сборятся два установщика, NSIS и MSI, плюс портативный архив; обновление идёт по
NSIS (`updaterJsonPreferNsis`: все установленные копии поставлены им же, иначе
клиент пошёл бы обновляться через `msiexec`). Манифест `latest.json` генерирует
tauri-action, режим установки `passive`, ключи подписи лежат в секретах сборки:
неподписанное обновление клиент не примет.

Апдейтер ходит не в `releases/latest`, а в собственный канал
`releases/download/windows-latest/latest.json`: в общем репозитории этот адрес
вычисляется GitHub как «последний обычный релиз», и при двух продуктах он
достаётся тому, кто вышел последним. Канал — релиз с постоянным тегом и одним
файлом, он обновляется на каждом выпуске.

Адрес `releases/latest` остаётся за настольным приложением: сборки 3.0.x и старше
вшили его в бильник и сменить уже не могут. Кто ещё занимает его — в
[docs/RELEASES.md](../RELEASES.md).

Профиль программы — `AppData\Roaming\com.foulnike.animori`:
`animori-settings.json` (настройки, пропуск, ключ облака), `animori-snapshot.json`,
`animori-dataset.json`. Имя каталога профиля — `identifier` из конфига; его смена
равносильна потере настроек у всех установленных копий.

## Экраны

Экран ничего не знает про сеть и хранение: читает память через
`collection-view.ts`, меняет список через `editEntry()`, имена берёт у
`media-title.ts`, облик — у `media-looks.ts`, взрослое отбирает через `adult.ts`.
Подписи — в `app/labels.ts`.

Десять экранов: главная, списки, статистика, история, поиск, карточка тайтла,
студия, плеер, настройки, журнал. Три с номером в адресе: карточка, студия, плеер.
В меню шесть: главная, списки, статистика, история, поиск, настройки; на карточку и
студию попадают из списков, поиска и чипов, на плеер — кнопкой «Смотреть», журнал
открывается адресом `#/log`.

Имена, меню, заголовки и глубина экрана лежат в `router/routes.ts` отдельно от
роутера: по глубине смена экрана получает направление. Отбор списка в адрес не
пишется — закладка, порядок и слово живут в `lists-keep.ts`, жанр витрины в
`home-keep.ts`.

### Тема

`styles/theme.css` — единственное место цвета, радиуса, тени, стекла и
длительностей. Тем три: тёмная, светлая и AMOLED; тема живёт атрибутом
`data-am-skin` на `<html>`, выбор хранится ключом `am_appearance`.

Акцент живёт дважды: `--am-accent` и `--am-accent-2` — готовые цвета, рядом
`--am-accent-rgb` и `--am-accent-2-rgb` — триплеты для альфы.
`amApplyAccentToDom()` из `packages/core/src/core/accent.ts` в слое приложения звать нельзя:
она подменяет цвет на триплет. Стекло не кладут на списковые строки — сотня
`backdrop-filter` за кадр; полоса музыки исключение, у неё `--am-glass-deep`.
`@media (prefers-reduced-motion: reduce)` гасит всё движение.

### Окна поверх экрана

Шторки: правка записи (`EntrySheet`), карточка человека (`PersonSheet`), отбор
подборки главной (`FilterSheet`) — все три на классе `.am-sheet` и через `Teleport`
в `body`. Панели поверх экрана: `ShotBox` (кадры и трейлер), `PeopleBox` (люди),
`TuneBox` (темы музыки), `CloudBox` и `ProxyBox` (настройки), а `PickBox` — ряд
выбора значения, из которого собраны последние две.

Шторка правит черновик: наружу уходит только «Готово», отдающее все расшедшиеся
поля разом, и на 900 мс становится «Сохранено». Крестик, подложка, Escape и
размонтирование черновик выбрасывают. В подвале у тайтла, который в списке есть,
живёт «Убрать из списка» — она зовёт `editEntry(…, 'remove', …)` и требует двух
нажатий, чтобы щелчок рядом с «Готово» не стоил записи.

### Журнал отладки

`utils/logger.ts`: запись, буфер и перехватчики. Ловятся `window.error`,
`unhandledrejection` и `app.config.errorHandler`/`warnHandler`, ставятся всегда, а не
по флагу: включил журнал — ошибки пошли сразу. Хвост лежит в `sessionStorage` под
ключом `animori_logs` и переживает перезагрузку страницы.

Модуль не импортирует настройки: иначе `logger → settings → мост` замкнулся бы
кольцом и в журнал перестали бы попадать ровно те слои, где он нужнее всего.
Флаг записи живёт в самом журнале (`setLogEnabled`), а значение приносит главный
запуск после чтения настроек. Ошибки Rust и плагинов Tauri в журнал не попадают —
это слепое зрение, и лечится оно только событием Tauri.

## Видео

```
core/video.ts        — виды источников, очередь, переключение
api/video-sources.ts — сеть: планировщик, кэш ответа, urlMonitor
api/aniliberty.ts    — история просмотра, качество, озвучка, дорожки
api/kodik.ts         — цепочка Kodik, расшифровка адресов
core/playable.ts     — метка доступности и очередь
screens/player-view.ts   — источник, дорожки, качество
screens/player-hls.ts    — hls.js, init, attach, переключение качества
screens/player-cast.ts   — панель системы и локальный экран
screens/player-input.ts  — клавиатура, кнопки, колёса, свайпы
screens/player-keep.ts   — место остановки и история просмотра
PlayerScreen.vue         — путь между плеером и списком
```

Правил у видео три, и все о памяти.

1. **Адрес — только на время показа.** Ссылка на поток и адрес картинки живут в
   переменных и умирают вместе с экраном. В IndexedDB, в снимок, в датасет и в
   localStorage они не попадают: подпись источника сама становится просроченной.
2. **Плеер не сети.** Он ходит только в `player-hls.ts`; сорсировка и выбор дорожки
   — `api/*` и `core/video.ts`. Ошибиться плеер может разве что на адресе, который
   уже отдают.
3. **Кэш ответа — до переключения.** Сорсировка не сетится на каждое движение
   человека, а кэш `urlMonitor` в памяти; `core/proxy.ts` ограничивает поток, а не
   адрес.

Метка доступности `PLAY1_` говорит, спросят ли источник зрителя, а не какая у него
скорость. Метка приходит из `playable.ts`, читается из склада, списком не
загрязняется и бывает трёх видов: «показывать» (список, студия, чипы),
«спросить» (плеер, кнопка «Смотреть» — работает всегда) и «не спрашивать».
Пока идёт тишина, источник не трогают: `markFirstPaint()` даёт секунду покоя после
первой отрисовки, `PAINT_REST_MS` — секунду после запроса, `BOOT_GRACE_MS` — четыре
секунды после пуска, `HUSH_TIME_MS` — десять минут после последней отметки.
Перервать тишину можно только жестом человека.

Цепочка Kodik: `должно_быть` → страница серии по номеру Шикимори → POST `/ftor` с
подписями `d_sign`/`pd_sign`/`ref_sign` → карта «высота → адреса» → выбор дорожки по
высоте окна. Адреса зашифрованы сдвигом букв и приходят со своим сроком, который
пересчитывает `expiryOf`. Один адрес часто лежит под двумя высотами — на замере
480 и 720 вели на 480.

Отрисованный кадр живёт за пределами окна, пока не пришло время его снять:
`requestVideoFrameCallback` даёт право кадру дожить, а `v.buffer` снимает его с
экрана.
